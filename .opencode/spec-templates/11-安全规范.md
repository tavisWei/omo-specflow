## 安全原则（Security Principles）

1. **最小权限**: 授予用户和服务最小必要权限
2. **纵深防御**: 多层安全防护
3. **默认安全**: 默认配置即为安全配置
4. **隐私保护**: 数据最小化收集，敏感数据加密存储

## 认证与授权

### 认证机制

**JWT Token**
```javascript
{
  "header": {
    "alg": "RS256",
    "typ": "JWT"
  },
  "payload": {
    "sub": "user_id",
    "role": "admin",
    "exp": 1699999999,
    "iat": 1699996399
  }
}
```

**Token 安全配置**
| 配置项 | 推荐值 |
|--------|--------|
| Token有效期 | 2小时(access) / 7天(refresh) |
| 算法 | RS256 (非对称) |
| 存储 | HttpOnly Cookie / 内存 |
| 传输 | 仅HTTPS |

### 授权模型

**RBAC (基于角色的访问控制)**
```
用户 → 角色 → 权限
  │
  └── admin ─── 所有权限
  │
  └── editor ─── 读写内容
  │
  └── viewer ─── 只读
```

**权限控制**
```javascript
// 路由守卫
const permissions = {
  '/admin': ['admin'],
  '/api/v1/users': ['admin', 'hr'],
  '/api/v1/orders': ['admin', 'sales']
};

// 验证逻辑
function checkPermission(user, path, method) {
  const requiredRoles = permissions[path] || [];
  return requiredRoles.includes(user.role);
}
```

## 数据安全

### 敏感数据定义
- 用户密码
- 身份证号
- 银行卡号
- 手机号
- 邮箱
- 位置信息
- 医疗健康数据

### 加密规范

**密码存储**
```javascript
// 使用 bcrypt
const bcrypt = require('bcrypt');
const saltRounds = 12;

async function hashPassword(password) {
  return bcrypt.hash(password, saltRounds);
}

async function verifyPassword(password, hash) {
  return bcrypt.compare(password, hash);
}
```

**敏感字段加密**
```javascript
// 使用 AES-256-GCM
const encrypted = encrypt(plainText, encryptionKey);
// 存储格式: iv:authTag:cipherText (base64)
```

**传输加密**
- 全站HTTPS (TLS 1.2+)
- 证书级别: EV 或 OV
- HSTS 启用

### 数据脱敏
```javascript
function maskPhone(phone) {
  return phone.replace(/(\d{3})\d{4}(\d{4})/, '$1****$2');
  // 13800138000 → 138****8000
}

function maskIdCard(idCard) {
  return idCard.replace(/(\d{6})\d{8}(\d{4})/, '$1********$2');
}

function maskEmail(email) {
  return email.replace(/(.{2}).*(@.*)/, '$1***$2');
  // john@example.com → jo***@example.com
}
```

## 接口安全

### SQL 注入防护
```javascript
// 正确: 使用参数化查询
const sql = 'SELECT * FROM users WHERE id = ?';
db.query(sql, [userId]);

// 错误: 字符串拼接
const sql = `SELECT * FROM users WHERE id = ${userId}`; // 危险!
```

### XSS 防护
```javascript
// 输入校验
function sanitizeInput(input) {
  return input
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#x27;');
}

// CSP Header
ctx.set('Content-Security-Policy', "default-src 'self'");
```

### CSRF 防护
```javascript
// 1. CSRF Token
ctx.cookies.get('csrf_token');

// 2. SameSite Cookie
ctx.cookies.set('session_id', token, {
  sameSite: 'strict'
});
```

### 请求限流
```javascript
const rateLimit = require('express-rate-limit');

const limiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15分钟
  max: 100, // 100次请求
  message: '请求过于频繁，请稍后再试'
});

app.use('/api', limiter);
```

## 安全响应流程

```
发现漏洞 ──▶ 评估等级 ──▶ 修复方案 ──▶ 紧急发布 ──▶ 复盘总结
                │
        P0/P1: 24小时内修复
        P2: 7天内修复
        P3: 下个迭代修复
```

### 漏洞等级
| 等级 | 定义 | 响应时间 |
|------|------|----------|
| P0 | 核心数据泄露 | 4小时 |
| P1 | 严重功能缺陷 | 24小时 |
| P2 | 中等安全问题 | 7天 |
| P3 | 低风险问题 | 下个迭代 |

### 安全事件与例外处理规则（Incident & Exception Handling）

**事件分级响应协议**

| 事件类型 | 触发条件 | 即时动作 | 升级路径 | 证据要求 |
|---|---|---|---|---|
| 数据泄露 | 敏感/机密数据外泄确认 | 隔离受影响系统、通知安全负责人 | P0 → CTO + 法务 | 访问日志、泄露范围评估报告 |
| 未授权访问 | 越权操作被检测到 | 封禁相关账户、审计操作记录 | P1 → 安全团队 | 审计日志、权限快照 |
| 依赖漏洞 | CVE 评分 ≥ 7.0 | 评估影响范围、制定修复计划 | P1/P2 → 开发负责人 | CVE 编号、影响分析、修复 PR |
| 配置错误 | 安全配置偏离基线 | 回滚配置、审查变更历史 | P2 → 运维团队 | 配置 diff、变更审批记录 |

**安全例外申请流程**

当业务需求与安全规范冲突时：
1. 提交例外申请，说明业务理由、风险评估、补偿控制措施
2. 安全审查人员评估并记录决策（approve / reject / conditional）
3. 批准的例外必须设定过期时间（最长 90 天），到期自动失效
4. 所有例外记录存入 `evidence/security/exceptions/` 目录，纳入 `08-traceability-matrix` 追踪
5. Agent 生成任务时：为每个活跃例外生成到期提醒任务和续期审查任务

**事件复盘要求**

每次 P0/P1 安全事件结束后，必须在 5 个工作日内产出复盘报告：
- 存储路径：`evidence/security/incidents/postmortem-{date}-{event-id}.md`
- 必须包含：时间线、根因分析、影响范围、修复措施、预防措施
- 复盘报告纳入 `08-traceability-matrix` 追踪，关联到对应的安全控制项

## 输入验证

### 验证原则
- 所有用户输入均不可信
- 服务端验证是最后防线，客户端验证仅为用户体验
- 白名单验证优于黑名单验证

### 通用验证规则
```javascript
// 字符串长度
input.length > 0 && input.length <= maxLength

// 数值范围
Number.isInteger(value) && value >= min && value <= max

// 正则验证
const patterns = {
  phone: /^1[3-9]\d{9}$/,
  email: /^[^\s@]+@[^\s@]+\.[^\s@]+$/,
  idCard: /^[1-9]\d{5}(19|20)\d{2}(0[1-9]|1[0-2])(0[1-9]|[12]\d|3[01])\d{3}[\dXx]$/,
  url: /^https?:\/\/.+/,
  ip: /^(\d{1,3}\.){3}\d{1,3}$/
};
```

### 文件上传验证
```javascript
function validateFile(file) {
  // 文件类型白名单
  const allowedTypes = ['image/jpeg', 'image/png', 'application/pdf'];
  if (!allowedTypes.includes(file.mimetype)) {
    throw new Error('不支持的文件类型');
  }

  // 文件大小限制
  const maxSize = 5 * 1024 * 1024; // 5MB
  if (file.size > maxSize) {
    throw new Error('文件大小超过限制');
  }

  // 文件名安全处理
  const safeName = file.originalName.replace(/[^a-zA-Z0-9._-]/g, '_');
  
  // 图片额外检查 (文件头魔数)
  const allowedMimes = {
    '89504e47': 'image/png',
    'ffd8ffe0': 'image/jpeg'
  };
}
```

### API 参数验证
```javascript
const Joi = require('joi');

const userSchema = Joi.object({
  username: Joi.string().alphanum().min(3).max(30).required(),
  email: Joi.string().email().required(),
  age: Joi.number().integer().min(0).max(150),
  role: Joi.string().valid('admin', 'user', 'guest')
});

function validateInput(data) {
  const { error, value } = userSchema.validate(data);
  if (error) {
    throw new ValidationError(error.details[0].message);
  }
  return value;
}
```

## 常见安全漏洞防护

### IDOR (越权漏洞)
```javascript
// 错误示例
app.get('/orders/:id', async (req, res) => {
  const order = await db.orders.findById(req.params.id);
  res.json(order);
});

// 正确示例: 校验资源所属
app.get('/orders/:id', async (req, res) => {
  const order = await db.orders.findById(req.params.id);
  
  if (order.userId !== req.user.id && req.user.role !== 'admin') {
    return res.status(403).json({ error: '无权访问' });
  }
  
  res.json(order);
});
```

### Path Traversal (路径穿越)
```javascript
// 错误示例
const file = req.query.filename;
res.sendFile(`/uploads/${file}`);

// 正确示例
const path = require('path');
const file = req.query.filename;
const safePath = path.resolve('/var/www/uploads', file);
if (!safePath.startsWith('/var/www/uploads')) {
  throw new Error('非法文件路径');
}
res.sendFile(safePath);
```

### SSRF (服务端请求伪造)
```javascript
// 错误示例
const url = req.query.url;
axios.get(url);

// 正确示例
const { URL } = require('url');
const parsedUrl = new URL(url);
if (!['http:', 'https:'].includes(parsedUrl.protocol)) {
  throw new Error('仅支持HTTP/HTTPS协议');
}
const blockedHosts = ['127.0.0.1', 'localhost', '0.0.0.0', '169.254.169.254'];
if (blockedHosts.includes(parsedUrl.hostname)) {
  throw new Error('禁止访问内网地址');
}
```

### XXE (XML外部实体)
```javascript
// 禁用 XML 外部实体
const xmlParser = new xml2js.Parser({
  parseAppData: false,
  externalEntities: false
});
```

### JSON注入
```javascript
// 输出编码
function jsonEncode(input) {
  return JSON.stringify(input)
    .replace(/</g, '\\u003c')
    .replace(/>/g, '\\u003e');
}
```

### 命令注入
```javascript
// 错误示例
const cmd = `ls ${userInput}`; // 危险!
exec(cmd);

// 正确示例: 使用execFile
const { execFile } = require('child_process');
execFile('ls', [userInput], (error, stdout) => {
  // 安全
});
```

## 安全测试 Checklist

### 开发阶段
- [ ] 代码审计: 手动审查安全关键代码
- [ ] 秘密扫描: 确保无硬编码密钥/凭证
- [ ] 依赖扫描: 使用 npm audit / Snyk / Dependabot

### 测试阶段
- [ ] 渗透测试: 模拟攻击者行为
- [ ] 模糊测试: 使用异常数据测试接口
- [ ] 配置审计: 检查安全相关配置
- [ ] 日志审计: 验证日志完整性

### 部署阶段
- [ ] 环境隔离: dev/staging/prod 网络隔离
- [ ] 备份验证: 定期测试备份可恢复性
- [ ] 证书检查: 有效期、强度、HSTS配置
- [ ] 监控告警: 安全事件实时告警

### OWASP Top 10 检查项
- [ ] A01: Broken Access Control - 权限验证全覆盖
- [ ] A02: Cryptographic Failures - 加密实现正确
- [ ] A03: Injection - SQL/XSS/命令注入防护
- [ ] A04: Insecure Design - 安全设计评审
- [ ] A05: Security Misconfiguration - 加固配置
- [ ] A06: Vulnerable Components - 依赖无漏洞
- [ ] A07: Auth Failures - 认证机制健壮
- [ ] A08: Data Integrity Failures - 数据一致性
- [ ] A09: Logging Failures - 日志记录完整
- [ ] A10: SSRF - 服务端请求伪造防护

## 发布阻断规则（Release Blocking Rules）

以下安全条件未满足时，禁止进入 Release Ready 阶段（对齐 `07-phase-gates`）：

| 阻断条件 | 判定标准 | 豁免流程 |
|---|---|---|
| SAST Critical/High 未修复 | 扫描报告中 Critical = 0, High = 0 | 需安全 Lead 签核例外 |
| 依赖漏洞 Critical 未修复 | `npm audit` / `snyk test` Critical = 0 | 需提交补偿控制方案 |
| 秘密泄露未清理 | secret-scan 发现数 = 0 | 不可豁免 |
| 权限矩阵验证未通过 | RBAC 测试 100% 端点覆盖且全部 PASS | 需安全 Lead 签核例外 |
| 渗透测试 Critical/High 未修复 | 渗透报告中 Critical = 0, High = 0 | 需 CTO 签核例外 |
| 安全例外超期未续期 | 所有活跃例外在有效期内 | 不可豁免 |

> Agent 生成任务时：为每个阻断条件生成对应的 CI/CD 检查步骤或手动验证任务。
