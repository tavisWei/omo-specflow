## 性能预算推导规则（Performance Budget Derivation Rules）

Agent 根据项目类型自动选择预算基线：

| 项目类型 | 核心指标 | 预算基线来源 | 调整因子 |
|---|---|---|---|
| Web SPA | LCP, FID, CLS, TTI, JS Bundle Size | Core Web Vitals "Good" 阈值 | 用户地域网络条件（3G/4G/WiFi） |
| Web SSR/SSG | TTFB, FCP, LCP, CLS | Core Web Vitals + TTFB ≤ 200ms | 服务器区域、CDN 覆盖 |
| REST API | P50/P95/P99 响应时间, QPS, 错误率 | 行业基准（简单查询 P95 < 100ms） | 数据量级、查询复杂度 |

## 性能回归阈值（Performance Regression Thresholds）

任何性能指标相对基线劣化超过以下阈值时，自动标记为回归并触发对应动作：

| 指标类别 | 回归阈值（相对基线） | 触发动作 | 阻断级别 |
|---|---|---|---|
| API P95 响应时间 | 劣化 > 20% | PR 标记 `perf-regression`，要求修复或说明 | 阻断合并 |
| API P99 响应时间 | 劣化 > 30% | 同上 + 通知性能负责人 | 阻断合并 |
| 页面 LCP | 劣化 > 15% 或超出 2.5s | PR 标记 `perf-regression` | 阻断合并 |
| 页面 CLS | 劣化 > 0.05 或超出 0.1 | PR 标记 `perf-regression` | 阻断合并 |
| JS Bundle Size | 增长 > 10% 或超出预算 | PR 标记 `bundle-size-alert` | 警告（不阻断） |
| 内存使用峰值 | 增长 > 25% | 通知开发负责人 | 警告（不阻断） |
| 数据库慢查询数 | 新增慢查询 > 0 | PR 标记 `slow-query` | 阻断合并 |
| 错误率 | 增长 > 0.1% 绝对值 | 通知开发负责人 | 阻断发布 |

### 基线管理规则

- 基线在每次成功发布后自动更新，存储于 `evidence/performance/baseline-{version}.json`
- 基线包含所有 `PERF-*` 编号指标的实测值
- 回归检测在 CI 中自动执行，对比当前分支与最新基线
- 基线更新需通过性能审查（对齐 `12-review-protocol`）

## 缓存策略

### 缓存分层
```
┌─────────────┐
│   Browser   │  ← LocalStorage, SessionStorage, Cache API
└─────────────┘
       │
┌─────────────┐
│   CDN       │  ← 静态资源缓存
└─────────────┘
       │
┌─────────────┐
│   Redis     │  ← 热数据, Session, 计数器
└─────────────┘
       │
┌─────────────┐
│   Database  │  ← 最终数据
└─────────────┘
```

### 缓存过期策略
| 数据类型 | TTL | 淘汰策略 |
|----------|-----|----------|
| 用户Session | 2小时 | LRU |
| 配置信息 | 24小时 | LFU |
| 热数据 | 5分钟 | LRU |
| 计算结果 | 10分钟 | LRU |

### 缓存示例
```javascript
// 多级缓存
async function getUserWithCache(userId) {
  // L1: 进程内缓存
  const l1 = memoryCache.get(userId);
  if (l1) return l1;

  // L2: Redis缓存
  const l2 = await redis.get(`user:${userId}`);
  if (l2) {
    memoryCache.set(userId, l2, { ttl: 60000 });
    return l2;
  }

  // L3: 数据库
  const user = await db.users.findById(userId);
  await redis.setex(`user:${userId}`, 300, user);
  return user;
}
```

### 并发用户计算

```
公式: 并发用户 = DAU × 平均页面数 / 每天秒数 × 峰值系数

示例:
- DAU: 10000
- 平均页面数: 5
- 每天秒数: 86400
- 峰值系数: 5

并发用户 = 10000 × 5 / 86400 × 5 ≈ 3 用户/秒 (RPS)
考虑5倍峰值: 15 RPS
建议压测目标: 50-100 RPS (预留空间)
```

### 后端优化方向

#### 1. 接口层优化
```javascript
// 请求合并
async function batchGetUsers(userIds) {
  const uniqueIds = [...new Set(userIds)];
  const cache = await redis.mget(uniqueIds.map(id => `user:${id}`));
  const missing = uniqueIds.filter((id, i) => !cache[i]);
  
  if (missing.length > 0) {
    const users = await db.users.findAll({ where: { id: missing }});
    await redis.mset(users.map(u => [`user:${u.id}`, u]));
    cache.push(...users);
  }
  
  return userIds.map(id => cache.find(c => c.id === id));
}

// 请求去重
const pendingRequests = new Map();
async function deduplicatedRequest(key, fn) {
  if (pendingRequests.has(key)) {
    return pendingRequests.get(key);
  }
  const promise = fn();
  pendingRequests.set(key, promise);
  try {
    return await promise;
  } finally {
    pendingRequests.delete(key);
  }
}
```

### 告警配置示例

```yaml
# Prometheus告警规则示例
groups:
- name: performance
  rules:
  - alert: HighResponseTime
    expr: histogram_quantile(0.95, rate(http_request_duration_seconds[5m])) > 0.5
    for: 5m
    labels:
      severity: warning
    annotations:
      summary: "High P95 response time"
      description: "P95 > 500ms for 5 minutes"

  - alert: HighErrorRate
    expr: rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m]) > 0.01
    for: 2m
    labels:
      severity: critical
    annotations:
      summary: "High error rate"
      description: "Error rate > 1%"

  - alert: DatabaseSlowQueries
    expr: rate(mysql_global_status_slow_queries[5m]) > 10
    for: 5m
    labels:
      severity: warning
    annotations:
      summary: "Many slow queries"
      description: "{{ $value }} slow queries per second"
```

## 可观测性指标要求（Observability Metrics Requirements）

### 必须采集的指标（Mandatory Metrics）

| 指标类别 | 指标名称 | 采集方式 | 聚合粒度 | 保留期限 |

| 请求级 | 响应时间分布（P50/P95/P99） | 应用埋点 / APM | 每端点 | ≥ 30 天 |

| 中间件级 | 数据库连接池使用率 | 应用埋点 | 每连接池 | ≥ 14 天 |
| 中间件级 | 缓存命中率 | Redis INFO / 应用埋点 | 每缓存键前缀 | ≥ 14 天 |
| 中间件级 | 消息队列消费延迟 | MQ API | 每 topic/queue | ≥ 14 天 |

## 发布阻断规则（Release Blocking Rules）

以下性能条件未满足时，禁止进入 Release Ready 阶段（对齐 `07-phase-gates`）：

| 阻断条件 | 判定标准 | 豁免流程 |
|---|---|---|
| 核心端点 P95 超标 | 所有"阻断发布 = 是"的端点 P95 ≤ 预算值 | 需性能负责人签核例外 + 优化计划 |
| 核心页面 LCP 超标 | 所有"阻断发布 = 是"的页面 LCP ≤ 预算值 | 需性能负责人签核例外 |
| 峰值压测未通过 | 3-5x 流量下错误率 < 1%，P95 < 2x 基线 | 需架构师签核例外 + 扩容方案 |
| 性能回归未修复 | 所有"阻断合并"级别的回归已修复或豁免 | 需性能负责人签核例外 |
| 内存泄漏未修复 | 长时间运行测试中内存增长 < 10% | 不可豁免 |
| 基线未建立 | `evidence/performance/baseline-*.json` 存在且有效 | 不可豁免 |
| 可观测性未就绪 | 所有必须采集指标已配置且可验证 | 需运维负责人签核例外 |

> Agent 生成任务时：为每个阻断条件生成对应的 CI/CD 检查步骤或手动验证任务。
