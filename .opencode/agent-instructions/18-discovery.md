# Discovery 阶段 Agent 指令 | Discovery Phase Instructions

> Agent 在 Discovery 阶段的完整行为规范：迭代生成 PRD（大纲优先）和竞品研究。

---

## 阶段定位 | Phase Position

**Discovery** 是上游文档链的第一个阶段，在 Constitution 之前执行。

```
Discovery → Architecture → Design → Constitution → Specify → Plan → Tasks → Implement → Complete
```

---

## 输入 | Input

- 用户的项目描述（来自 `/spec-start` 面试或直接输入）
- 面试结果 JSON（项目类型、技术偏好、核心功能）

---

## 输出 | Output

- `.spec/PRD.md` — 产品需求文档（大纲优先迭代）
- `.spec/COMPETITOR-RESEARCH.md` — 竞品研究文档

---

## 子阶段 1：PRD 大纲优先迭代 | PRD Outline-First Iteration

### 步骤 1.1：生成一级大纲骨架

**行为**:
1. 读取用户输入和面试结果
2. 生成 PRD 一级大纲骨架（仅 5 个章节标题 + 1 句引导语）
3. 输出骨架，等待用户确认

**一级大纲结构**:
1. 项目背景与定位
2. 目标用户与场景
3. 核心功能范围
4. 非功能要求
5. 约束与排除

**输出格式**:
```markdown
## PRD 一级大纲

### 1. 项目背景与定位
本项目旨在……，面向……用户，解决……问题。

### 2. 目标用户与场景
核心用户群体为……，主要使用场景包括……

### 3. 核心功能范围
- 功能 A
- 功能 B
- 功能 C

### 4. 非功能要求
性能/安全/可用性/可观测性各有基本要求。

### 5. 约束与排除
技术/资源/合规/时间约束；明确不在范围内的功能。

---

请确认大纲是否需要调整，或输入"已确认大纲"进入二级细化。
```

### 步骤 1.2：用户确认或调整

**行为**:
- 等待用户反馈
- 如用户要求调整，修改大纲后重新输出
- 如用户输入"已确认大纲"，进入步骤 1.3

### 步骤 1.3：二级细化

**行为**:
1. 按章节顺序填充详细内容
2. 每个章节填充后可让用户确认，或一次性填充全部章节
3. 用 `[NEEDS CLARIFICATION]` 标记不确定项（**每个文档最多 3 个**）

**质量标准**:
- 每个一级章节至少 3 个二级条目
- P0 功能有可量化验收标准
- 非功能要求已量化
- 总长度 ≥150 行

---

## 子阶段 2：竞品研究 | Competitor Research

### 步骤 2.1：提取研究范围

**行为**:
1. 从 PRD.md 提取产品定位和核心场景
2. 推导 GitHub 搜索关键词

### 步骤 2.2：搜索竞品

**行为**:
1. 使用 `grep_app_searchGitHub` 工具搜索 GitHub 竞品
2. 至少找到 3 个相关项目
3. 记录 Stars、语言、相关度

### 步骤 2.3：分析竞品

**行为**:
1. 功能对比：将 PRD P0 功能与竞品对比
2. 技术栈对比：分析竞品技术选型
3. UX 对比：提取亮点和避坑点
4. 差异化机会：总结本项目独特价值

**质量标准**:
- 至少分析 3 个竞品
- 功能对比表覆盖所有 P0 功能
- 有明确的差异化建议

---

## 完成条件 | Completion Criteria

调用 `validatePhaseCompletion("discovery")` 必须返回 `{ valid: true }`：
- `.spec/PRD.md` 存在且包含 5 个一级章节
- `.spec/COMPETITOR-RESEARCH.md` 存在且包含至少 3 个竞品分析
- 用户已确认 PRD 大纲

---

## 质量门控 | Quality Gate

| 检查项 Check | 通过标准 Pass Criteria |
|---|---|
| PRD 大纲确认 | 用户已输入"已确认大纲" |
| PRD 完整性 | 5 个一级章节全部有内容 |
| 竞品数量 | ≥3 个 |
| 功能覆盖 | P0 功能全部在对比表中 |

---

## 禁止事项 | Must NOT Do

- 不要在用户确认大纲前填充二级内容
- 不要跳过竞品研究直接进入 Architecture
- 不要使用模糊词（如"高性能"）而不量化
- 不要生成空章节

---

- [ ] PRD 5 个章节全部有内容
- [ ] 竞品研究已搜索 GitHub
- [ ] 至少 3 个竞品已分析
